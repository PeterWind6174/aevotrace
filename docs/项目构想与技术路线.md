# Aevotrace：跨架构、跨系统的执行引导离线重编译

更新日期：2026-11-05。版本：0.2。状态：架构草案；main 已有执行核心和双 GUI 实验，但尚未连通为产品转换器，无产品性能结论。当前集成状态见 [合并记录](p0/INTEGRATION-20261105.md)。

用户已将原来的 AArch64/Apple Silicon 研究构想扩展为通用平台转换工具，首个方向改为 Windows x86-64 → macOS ARM64 GUI 应用。产品要求以 [需求规格](需求规格.md) 为准，阶段计划见 [开发计划](开发计划.md)。原 0.1 文档保留在本地 `.local/history/20261105_需求扩展前/`。

## 1. 架构应分开的维度

| 维度 | 首版 | 扩展方式 |
| --- | --- | --- |
| 源二进制 | PE32+、EXE/DLL、资源 | 增加格式 frontend |
| 源 ISA | x86-64 | 增加指令语义 frontend |
| 源平台语义 | Windows 用户态 ABI 与选定接口 | 增加平台 personality |
| 目标 ISA | ARM64 | 增加编译 backend |
| 目标系统 | macOS | 增加运行时、链接与打包 backend |
| 平台适配 | `compat` / `native` | 独立能力表和实现 |

不能把 LLVM 有某个目标后端当成该系统组合已实现。源操作系统 ABI、内存、异常、模块和 UI 语义仍需适配。

## 2. 逻辑组件

1. 项目与输入管理：输入模块、资源、依赖、内容身份与可选元数据。
2. 装载与代码发现：PE 解析、重定位、导入/导出、静态发现、执行记录和动态版本。
3. 源架构语义：x86-64 指令、标志位、内存序、SIMD/浮点及 Guest 状态。
4. 共享执行核心：解释/参考执行、AOT 调度、JIT 回退、异常、安全点和代码失效。
5. 离线编译：可重定位表示、优化、Host 代码和依赖信息。
6. 平台接口桥接：Guest 调用约定、Windows 类型与句柄、回调、Host 调用约定。
7. 平台适配后端：兼容实现或 macOS 原生适配，使用一致的应用可见接口契约。
8. 产物构建与诊断：应用包、签名、资源、manifest、能力/性能报告。

这是组件边界，不是已冻结的目录和类设计。P0 以验证结果选择依赖，P1 才冻结公共接口。

## 3. 静态发现与执行发现共同工作

不强制所有代码必须先实际执行才能离线处理。PE 元数据、符号、保守控制流分析先发现静态代码；准备执行补充间接目标、动态装载、代码版本与 profile。

有限 Trace 不证明完整覆盖。已发现基本块保留分支、循环和输入语义，可在新输入下重新组合执行。新间接目标和动态代码通过解析、JIT 或明确失败处理。

第一版优先得到可验证的机器代码转换闭环，不以高阶 LLVM lifting 或跨函数优化为前提。候选方案比较正确性、AOT 可加载性、JIT 交接、跨架构能力和许可。

## 4. 执行和代码版本

准备阶段：建立输入身份 → 采集与合并 → 验证代码版本 → 离线构建 → 原子发布不可变 artifact。

正式运行：校验 artifact → 绑定模块与映射 → 优先 AOT → 未命中 JIT → 记录新增内容 → 下一轮离线构建。

保留解释器用于指令测试和已实现范围内的保守回退。用户选择的正式运行路线允许 JIT，不要求首版另行交付严格 No-JIT 产品模式。

动态代码首版保留 Guest 生成过程，复用 Host 翻译结果。捕获字节不能证明可跳过生成器的分配、函数表或其他副作用。

## 5. 必须统一的核心契约

### 5.1 Guest 状态和内存

x86-64 状态按源 ISA 定义，至少包括通用寄存器、RIP、RFLAGS、所需 SIMD/浮点状态和线程环境。不能沿用旧方案的 AArch64 X0–X30 ABI。

Guest 指针、Host 指针和窗口/文件等句柄需要明确分类。统一内存模型处理地址范围、权限、访问失败、跨页与原子操作。x86 与 ARM 的指令及内存顺序差异必须验证，不能依靠同地址映射推断等价。

### 5.2 AOT/JIT 交接

两者共享 Guest 状态、helper ABI、异常和退出原因。初期在块边界同步，优化不能破坏故障位置和可恢复状态。GUI 回调从 Host 返回 Guest 同样经过该契约。

### 5.3 模块和平台调用

处理 PE 导入/导出、延迟装载、TLS、初始化、资源和应用需要的异常/栈展开。Windows x64 与 macOS ARM64 调用约定由显式桥接转换；不能直接把 Guest 函数指针传给 AppKit 当 Host 回调。

## 6. 两个 GUI/系统后端

`compat` 兼容已支持的 Windows 行为；候选兼容运行库能否在 macOS ARM64 中按预期集成，必须通过样例和许可证核查。

`native` 通过明确支持的 API/控件映射调用 macOS 原生框架。Windows 窗口过程、消息队列、同步消息与重入不能简单替换为一次异步 UI 更新。AppKit 主线程约束、模态循环、线程间消息和 Guest 回调进入设计。

两种后端都可能调用 macOS，但 `native` 必须对已支持 GUI 元素使用原生框架，而非重命名兼容后端。纯 `native` 遇到未支持能力应失败或明确报告；后续可另设 mixed 模式，不默认引入。

首版使用同一组自编 GUI 程序验证两个后端。真实应用是否可用，以具体框架和 API 覆盖为准。

## 7. Artifact、映射与重定位

artifact 至少记录：输入内容身份、模块偏移/Guest 地址与字节依赖、代码版本、翻译器及 runtime ABI、源/目标特性、适配模式、后端版本、helper ABI、重定位与优化假设。

跨次稳定身份与本次映射生命周期分离。不持久化 Host 裸指针。即使字节一致，Guest PC、字面量和映射不同仍可能需重新绑定。若命中正确性依赖字节相等，初期完整比较依赖字节。

代码修改、权限转换、解映射、同址重分配和跨页依赖必须撤销入口与链接。仅入口检查无法解决执行中的并发改写；未支持的并发自修改配置明确拒绝。

## 8. macOS 加载与独立运行

离线产物优先评估正常签名加载的 ARM64 Mach-O 模块，用数据表完成动态绑定。JIT 回退独立遵循目标版本的 MAP_JIT、写保护和指令缓存要求。AOT 不自动免除可执行内存或签名规则。

`.app` 包含许可兼容组件、资源与配置。新增 Trace/JIT 缓存写入应用数据或缓存目录，不能改写已签名包。包内依赖检查须证明主执行链无需 Rosetta 和开发机特有路径。

## 9. 双机验证

Windows x64 主机通过 `ssh win` 编译和运行参考样例，采集业务输出、文件结果与事件日志。Windows 原生参考执行不等于获得指令 Trace；采集 Trace 需单独选型并测量干扰。

Mac 负责目标 ARM64 构建、AOT/JIT 验证、两个后端和打包。报告绑定代码版本/输入哈希、二进制哈希、配置和场景。SSH GUI 不一定出现在交互桌面；GUI 验证检查会话并按需请求用户操作。

## 10. 与旧构想的关系

保留动态代码捕获、多轮合并、版本依赖、正确失效和回退；取消首版同 ISA 假设。Switch/Horizon/GPU 后置，不进入首版关键路径。旧 M0–M4 是历史计划，后续采用 [P0–P6](开发计划.md)。

BinRec、持久化翻译缓存、Native Execution 等仍提供局部参考，其平台和性能结果不外推为本项目能力。资料与边界见 [REFERENCES.md](REFERENCES.md)。
