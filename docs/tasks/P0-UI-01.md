## 目标与范围

- 可观察的完成结果：
  1. Windows x64 测试程序（建议 DLL，导出 `WndProc`/业务状态读取函数）在 Windows 编译并运行，固定源码/二进制 SHA-256；包含窗口、按钮、文本框、菜单或等价控件、中文/Unicode、`WM_COMMAND` 回调修改业务状态。
  2. macOS harness 实际执行该输入中的 x64 机器码（可使用 Unicorn 等仅用于 P0 的临时执行桥接，必须明确标注非产品核心），由 Host 创建窗口并把事件送入 Guest `WndProc`；Host 不重写 Guest 业务逻辑。
  3. `compat` 后端：呈现 Windows 窗口/控件语义的兼容后端；`native` 后端：真实使用 AppKit `NSWindow`/`NSButton`/`NSTextField` 等原生控件，事件同步回调 Guest 并正确返回；两者都保留 Windows ABI/消息语义的可验证子集。`compat` 候选必须说明目标架构与是否依赖 Rosetta；若本 spike 只是语义 harness、未选定最终兼容实现，报告必须明确写“P0-ui-harness，不是最终 compat 运行库”，D3 保持未决。
  4. 加测同步回调重入（Host→Guest→Host）、最小模态交互和线程退出；记录消息序列、业务状态、Guest 指令/回调计数。`native` 记录 `NSThread.isMainThread`、窗口/控件创建线程和回调线程。
  5. `native` 未支持能力明确失败/报告，不静默回退 `compat`；至少一个负例证明未支持接口不会进入 compat。
  6. 反伪证：Guest 业务状态必须来自同一 Guest 二进制哈希的实际 x64 代码执行；至少一个输入文本/按钮序列变异会改变业务状态/消息序列；Host 代码不得直接修改 Guest 业务状态。
- 允许修改的文件或组件：仅 `.worktrees/p0-ui/` 下的 `spikes/p0-ui/` 与任务报告；不修改 `main` 或其他 worktree。
- 明确不包含的内容：完整 Win32 API、真实应用、AOT/JIT 产品化、最终 `.app` 打包/签名、像素级 UI 一致性。
- 需要的依赖及许可记录：Unicorn（如使用，记录版本/许可证，且仅 P0）、PE 解析库、AppKit/Cocoa；不得把临时桥接写成产品能力。
