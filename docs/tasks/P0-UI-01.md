## 目标与范围

- 可观察的完成结果：
  1. Windows x64 测试程序（建议 DLL，导出 `WndProc`/业务状态读取函数）在 Windows 编译并运行，固定源码/二进制 SHA-256；包含窗口、按钮、文本框、菜单或等价控件、中文/Unicode、`WM_COMMAND` 回调修改业务状态。
  2. macOS harness 实际执行该输入中的 x64 机器码（可使用 Unicorn 等仅用于 P0 的临时执行桥接，必须明确标注非产品核心），由 Host 创建窗口并把事件送入 Guest `WndProc`；Host 不重写 Guest 业务逻辑。
  3. `compat` 后端：呈现 Windows 窗口/控件语义的兼容后端；`native` 后端：真实使用 AppKit `NSWindow`/`NSButton`/`NSTextField` 等原生控件，事件同步回调 Guest 并正确返回；两者都保留 Windows ABI/消息语义的可验证子集。
  4. 加测同步回调重入（Host→Guest→Host）、最小模态交互和线程退出；记录消息序列、业务状态、Guest 指令/回调计数。
  5. `native` 未支持能力明确失败/报告，不静默回退 `compat`。
- 允许修改的文件或组件：仅 `.worktrees/p0-ui/` 下的 `spikes/p0-ui/` 与任务报告；不修改 `main` 或其他 worktree。
- 明确不包含的内容：完整 Win32 API、真实应用、AOT/JIT 产品化、最终 `.app` 打包/签名、像素级 UI 一致性。
- 需要的依赖及许可记录：Unicorn（如使用，记录版本/许可证，且仅 P0）、PE 解析库、AppKit/Cocoa；不得把临时桥接写成产品能力。

- macOS 目标执行步骤：构建 harness；分别运行 `compat` 与 `native`；自动日志记录窗口创建、按钮点击、文本修改、同步重入、模态返回、线程退出；截图/人工观察步骤单列。
- 预期业务输出、状态或副作用：两种后端得到相同业务状态；`native` 能证明使用原生控件（视图类名/对象类型/截图）；无静默回退。
- GUI 自动/人工部分：自动部分必须实际启动窗口并驱动事件；人工部分（外观、焦点、模态观感）未完成时标为 `待人工验证`。
